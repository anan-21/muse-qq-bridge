# 这次方法里最值得留下的点

## 1. 先选身份和通道，再写转发

最初的个人 QQ 挂接路线被平台以设备风险为由下线。软件仍在更新不能保证账号会话得到平台支持。最终采用官方机器人的独立应用身份，大号仅作为聊天对象。

新方案使用平台提供的机器人能力。是否开放个人开发者沙箱单聊，以控制台实际权限为准。

## 2. 大脑和手分开

机器人适配器不接模型。它只把事件送到桥、把原智能体的答案送回 QQ。把第二个模型接在服务器上虽然也能回答问题，却不等于原 Muse 会话上线。

## 3. Content-Length 不是所有 HTTP 请求都有

先前对接时，事件使用 chunked 编码，旧请求读取层只认 Content-Length，导致 HTTP 400 和 pending 一直为 0。修复时只改正文读取，继续按解码后的精确原始正文计算 HMAC，不改白名单和密钥。

本仓库保留对应回归测试：UTF-8 跨块、有界正文、错误签名、重复事件、歧义 framing。先模拟成功再让本人重发测试，避免无效扫码和反复发送。

## 4. 地址、端口、登录态分开核对

`127.0.0.1` 指的是当前运行环境的 loopback。容器里的 localhost 不自动指向宿主机。排查发送失败时，要在调用方同一环境查看真实地址、TCP 监听和上游请求结果。

Web 管理页在线也不等于 OneBot 发送端口在线。`Connection refused` 是没有到达 HTTP 服务，不该归咎于模型没有回复。

## 5. 发送确认必须落到回执

检查 HTTP 状态、业务码和消息 ID；没有回执就不能报成功。官方 SDK 的默认重试行为也要读源码核对，不能凭方法名推断它只发一次。

发送前持久化占位。未知结果留待人工判断，不“再试一次看看”。入站可以依靠稳定消息 ID 幂等重试；出站不能把这套逻辑直接照搬。

## 6. OpenID 不等于 QQ 号

官方事件的用户标识是 `user_openid`。用临时绑定语句确认主人，再映射到桥的本地数字兼容别名。任意首个发消息的人不应自动成为管理员。

## 7. 进程启动和服务可用是两件事

原始迁移中，一次性切换辅助命令返回了退出码 1；独立复查却确认新地址已生效、鉴权没变、health 正常，之后真实 QQ 收发通过。原始错误文本未保留，因此具体原因仍不能认定。

公开版本不分发这份现场切换脚本。启动后用有界 health 探测检查服务；不要因为一条辅助命令退出非零就盲目重复重启。保留脱敏 stderr 和各层验证结果，才能区分操作失败、探测过早和诊断缺口。

## 8. 离线依赖要按目标 Python 检查

跨平台下载 wheel 时，二进制目标参数不代表所有条件依赖都按目标解释器解析。曾在 Python 3.14 下载 Linux/Python 3.12 wheel 后遗漏 `typing_extensions`。

需要离线部署时检查目标环境的 `Requires-Dist`、摘要和完整依赖闭包，再到目标解释器安装验证。当前公开版的常规安装直接在目标服务器解析依赖，不打包个人依赖缓存。
